# EconMark 数据治理与账户规范

## 1. 决策边界

EconMark 3.0 采用一个统一系统：公开访客可运行原创合成样例；创建账户并登录后，可上传真实手写作答、运行单份或批量评分、打印反馈并访问永久历史。系统不要求用户在上传前勾选“匿名作答/隐私声明”，也不以弹窗区分所谓演示系统与真实系统。

这一交互决策不等于取消治理责任。部署单位仍应在页面常驻说明、校内制度和供应商合同中明确用途、处理地点、模型子处理方、访问范围和永久保存后果。是否可处理真实学生材料应由学校决定，而不是由一个浏览器复选框替代。

## 2. 账户与登录数据

SQLite 中保存以下账户数据：

| 类别 | 字段 | 保存形式与用途 |
|---|---|---|
| 身份 | `account_id` | 随机 UUID 前缀 ID；作为所有权主键 |
| 登录名 | `username` | 3–60 个 Unicode 字母、数字、点、下划线或连字符；不区分大小写唯一 |
| 显示名 | `display_name` | 界面显示，不作为授权依据 |
| 密码 | `password_hash` | Argon2id；不保存也不记录明文密码 |
| 时间 | `created_at`, `updated_at`, `last_login_at` | 审计与故障排查 |
| 状态 | `active/disabled` | 预留管理停用能力 |

会话使用 256 位随机令牌。浏览器只通过 `HttpOnly; SameSite=Strict` Cookie 接收原始令牌，数据库仅保存 SHA-256 摘要。CSRF 令牌独立生成；所有 POST 请求还必须通过同源检查。会话记录可包含截断后的 User-Agent 与客户端 IP 的 SHA-256 摘要，用于异常登录诊断，不保存明文 IP。

## 3. 永久评分记录

每次成功上传并评分后，服务器保存：

- 原始文件、MIME 类型、字节数和 SHA-256；
- 账户 ID、批次 ID、学生化名编号与原文件名；
- 图像验证、确认或自动门控后的转写；
- 教师确认的题目、评分标准及其哈希；
- 初评、独立复评、一分差异裁决、证据表和置信度；
- 中英双语反馈、两个优先改进点及一至两道针对性巩固题；
- 人工或自动终审、调整理由、时间和策略版本；
- Schema、工作流、提示词和模型版本。

记录的 `retention_policy` 固定为 `permanent_no_automatic_deletion`。代码没有定时清理、单条删除、批量删除或账户删除 API；旧文件不会为了释放空间而被自动删除。账户达到配置的永久存储配额后，只拒绝新上传。

## 4. 所有权与访问

所有评分、批次和图片行都包含 `account_id`。读取 `/api/runs/:id`、修改终审决定和读取 `/api/images/:id` 时，服务器同时匹配当前会话账户；URL 不构成授权。图片通过受认证的同源 API 流式返回，不放入公开静态目录，不生成永久公开链接。

所有注册账户拥有相同产品功能，不存在只在前端隐藏的“教师特权”。将来如引入管理员、学校或共享班级，必须新增显式角色/成员关系表和服务器端授权测试，不能复用显示名判断权限。

## 5. 容量与可用性

永久保存与开放注册会造成不可逆的磁盘增长，因此必须同时采用：

- 可配置单文件、单批总量、批次人数、并发和账户配额；
- 注册/登录 IP 速率限制与账户评分速率限制；
- VPS 磁盘、inode、SQLite WAL、错误率和供应商成本监控；
- 达到容量阈值时停止新增，不删除旧资料；
- SQLite 与 `images/` 的成对、一致性备份以及定期恢复演练。

默认值用于一台中小型 VPS，不是容量承诺。批次并发应根据 CPU、内存和模型 API 限流逐步提高；较大的批次仍按“一名学生一个独立评分请求”处理，避免整班上下文污染和全批失败。

## 6. 日志与备份

普通应用日志只记录时间、路由、状态码、稳定错误码、耗时和非内容型运行 ID；不得记录密码、会话令牌、CSRF 令牌、API 密钥、base64 图片、学生转写、评分标准或完整模型响应。

“上传图片永不自动删除”要求备份策略同样保守：生产备份不得仅保留数据库而遗漏原图，重建 VPS 不得指向临时目录。备份加密、访问权限和恢复目标由部署方管理；删除旧备份会减少可恢复历史，若采用该操作必须形成独立、明确的运维政策，而不能由 EconMark 应用静默执行。

## 7. 上线前的制度事项

在真实课堂使用前，至少记录：系统责任人、学校授权、VPS 地区与运营者、模型供应商及子处理方、数据跨境情况、账户发放/停用流程、学生化名规则、事故响应、备份管理员、永久保存依据和人工申诉/改分流程。EconMark 提供技术审计，不替代学校政策或法律审查。
